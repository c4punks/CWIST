Detailed Description

mbedTLS implementation of the CWIST TLS backend seam.

Implements every cwist_mtls_* function declared by the shim headers in src/security/tls/shim/openssl/ on top of mbedTLS (mbedtls_ssl_* and friends). Call sites keep their OpenSSL-shaped code; the shim macros map it here, so a CWIST_TLS=mbedtls build contains no BoringSSL objects or symbols.

Scope and honest limitations (all relative to the BoringSSL backend):

  • TLS 1.2 + 1.3, server and client, ALPN, session cache and pre-fork shared session tickets are fully supported.
  • Session-ticket keys are armed deterministically from the CWIST shared ticket key (carried in SSL_CTX ex_data by https.c), so tickets resume across forked workers and certificate hot reloads, as with BoringSSL. TLS 1.3 NewSessionTicket issuance is suppressed, though: mbedTLS writes it after the handshake wrap-up, which races clients that close right after their Finished (ECONNRESET on the trailing write fails the whole handshake). TLS 1.2 session-ID/ticket resumption via the server cache keeps working.
  • SSL_session_reused() always reports 0: mbedTLS exposes no public per-connection resumption flag, so the cwist_https_tls_handshakes_resumed_total() counter stays 0.
  • AIA chain autoload (tls_chain.c), ECH and the hybrid PQC group list are BoringSSL-only; see tls_chain.c / ech.c / pqc_layer.c.
