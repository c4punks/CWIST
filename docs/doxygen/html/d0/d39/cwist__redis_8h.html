◆ cwist_redis_reply_t

typedef struct cwist_redis_reply cwist_redis_reply_t

Parsed RESP2 reply tree.

Supported since v3.8. Returned by cwist_redis_command_argv_reply(). type is the RESP type byte: '+', '-', ':', '$', '*'. For '-', str holds the error text and the command reports failure. For ':' and '$', str is the textual value (always NUL-terminated; use len for exact bulk length) and integer holds the parsed number. For '*', element/elements hold children.

size_t  argc,
const void *const *  argv,
const size_t *  argv_lens,
unsigned  timeout_ms,
cwist_redis_reply_t **  reply 
)

Run one binary-safe pooled command under a single deadline.

One CLOCK_MONOTONIC budget of timeout_ms covers waiting for a free pool connection, reconnecting a discarded connection, writing the request, and reading the complete reply. The pool's legacy blocking APIs keep their unbounded behavior; pool creation still performs blocking DNS and connects.

Connection safety: an idle connection with buffered or readable bytes, a hang-up, or a previous failure is discarded before use and replaced by a new connection to the peer address resolved by cwist_redis_pool_create() (no DNS at request time). Once any request byte has been written the command is never retried; on timeout, transport error, or malformed reply the connection is closed so a late reply can never be read by a later caller. SIGPIPE is not raised. Reply parsing is strict RESP2 with limits (8 nesting levels, 65536 nodes, 8 MiB per bulk string, 16 MiB of payload, 8 KiB status/header lines).

Replacement connections start fresh: AUTH, SELECT, HELLO and other per-connection state are not replayed. Pools used with this API must not rely on such state. Legacy pooled calls may also receive a fresh connection after a timed call discards a socket. Use a dedicated default-state pool.

Reply types follow cwist_redis_reply_t. A null bulk string is '$' with str == NULL and integer == -1; a null array is '*' with elements == 0 and integer == -1. Nested '-' elements are data.

The pool must have been created by the calling process (a pool inherited across fork() is rejected without touching it) and must not be destroyed concurrently with this call.

Parameters
poolPool from cwist_redis_pool_create().
argcNumber of arguments (1 .. 1048576).
argvArgument pointers; an entry may be NULL only if its length is 0.
argv_lensByte length of each argument (frame limited to 512 MiB).
timeout_msTotal budget in milliseconds; must be positive.
replyOut: reply tree on success (free with cwist_redis_reply_free()); always set to NULL on failure.
Returns
CWIST_ERR_INT16 error whose err_i16 is 0 on success or a negative errno: -EINVAL invalid argument or timeout 0; -EPERM pool inherited from another process; -ETIMEDOUT budget exhausted; -EIO connect, send, or receive failure, or peer EOF; -EPROTO malformed or over-limit reply; -EBADMSG top-level Redis error reply (the connection stays in sync and reusable); -ENOMEM allocation failure.

Deadline-bounded pooled command; see cwist_redis.h for the contract.

Subscribe to channels on a dedicated connection.

This call blocks the current thread and invokes cb for each message. Use it inside a background thread. To stop, call cwist_redis_close() from another thread (the read loop will exit on socket error).

Parameters

Returns
0 when stopped cleanly, -1 on error.

Subscribe to channels and run a blocking message loop, invoking the callback for each incoming message.
