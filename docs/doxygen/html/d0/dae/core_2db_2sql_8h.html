Insert a (possibly broken) JSON object into a table with self-healing.

Applies the self-healing layer to json_str, validates the result with the Zod-like strict validator (if a schema is provided), then generates and executes an INSERT SQL statement.

Returns an error when:

  • the JSON cannot be healed to a confidence >= cfg->threshold
  • Zod validation rejects the healed object (missing required fields / wrong types)
  • the SQL execution fails
Parameters
dbOpen database handle.
tableTarget table name (used verbatim in the SQL).
json_strRaw (possibly malformed) JSON string.
schemaSchema used for L2 healing and strict validation (may be NULL).
heal_cfgHealing configuration (may be NULL for defaults).
Returns
cwist_error_t; err_i16 == 0 on success.

const void *  buf,
size_t  len,

)

Open a CWIST database from an in-memory SQLite image.

Open a database from an in-memory SQLite image (blob), e.g. one fetched by a WASM/edge host instead of a filesystem path. The image is copied with sqlite3_malloc64(), so the caller keeps ownership of buf.

Parameters
dbReceives the handle (NULL on failure).
bufSerialized SQLite database image.
lenImage length in bytes.
readonlyNon-zero opens the image read-only (writes fail with SQLITE_READONLY); zero allows the in-memory db to grow.

The image is copied into SQLite-owned memory (SQLITE_DESERIALIZE_FREEONCLOSE), so the caller keeps ownership of buf. Same connection defaults as cwist_db_open(): FULLMUTEX, no extra pragmas.

Parameters
dbReceives the handle (NULL on failure).
bufSerialized SQLite database image.
lenImage length in bytes.
readonlyNon-zero opens the image read-only; zero allows growth.
Returns
Tagged CWIST error describing success or failure.
