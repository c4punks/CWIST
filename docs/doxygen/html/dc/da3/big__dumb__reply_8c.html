Detailed Description

Opportunistic response cache that stores stable GET replies in memory or on disk.

Concurrency model: bucket chains are published with a CAS push and entry nodes are never freed until destroy (retired entries are tombstoned), so readers walk without locks. The response blob lives behind an atomic pointer per entry; writers swap it with one exchange and retire the predecessor through libttak EBR, which guarantees a swapped-out blob outlives every reader that entered its epoch before the swap. Only the janitor (TTL/byte-trim/disk spill, every 64 learns) and the disk-fallback path take the context mutex.

Publish a stable reply together with a hit-time revalidation hook.

Cache a response whose backing value may change over time.

On every subsequent hit the hook is invoked and, if it reports fresh bytes, the entry's blob is swapped to the callback-provided buffer through one pointer exchange. The hook is published before the blob so a reader never observes a revalidatable blob without its hook. In disk mode the observation is written to SQLite instead (hook not persisted). Triggers the janitor tick periodically.
