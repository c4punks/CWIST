Detailed Description

Reverse proxy: forward HTTP/1.1, HTTP/2 and HTTP/3 requests to HTTP/1.1 upstreams.

Rules are registered process-wide, then cwist_proxy_listen() builds one front application per origin port and serves them:

cwist_proxy.h2_enabled = true;
cwist_proxy.h3_enabled = true;
cwist_proxy.http_auto_promote = true;
cwist_proxy_route("http://api.example.com:8080", "/api", "http://127.0.0.1:3000", "/v1");
cwist_proxy_port_forward(8081, 4000);
return cwist_proxy_listen();

Security defaults (not configurable in this version):

  • The upstream comes only from a registered rule, never from the request.
  • Requests are parsed and re-serialized; raw bytes are never forwarded. Header names must be tokens and values must not contain CR, LF or NUL, whichever protocol they arrived on.
  • Hop-by-hop headers, and every header the Connection header names, are dropped in both directions.
  • X-Forwarded-For/-Host/-Proto, X-Real-IP and Forwarded sent by the client are discarded; the proxy writes its own X-Forwarded-* values.
  • Paths with dot segments, encoded slashes or backslashes, malformed percent escapes or control bytes are rejected with 400.
  • Upstream redirects are returned to the client, never followed, and upstream TLS certificates are verified.

Every front protocol (HTTP/1.1, h2, HTTP/3) is forwarded off the serving thread through cwist_async_defer(); the QUIC engine keeps serving other streams while an upstream answers.

On HTTP/1.1 fronts (cleartext and TLS), response headers and body chunks stream to the client as they arrive from the upstream (bounded by cwist_proxy_config::max_response_bytes); HTTP/2 and HTTP/3 fronts assemble the response on the worker before handing it to the connection thread. WebSocket upgrades and CONNECT tunnels pass through as raw byte relays on cleartext HTTP/1.1 fronts (and return 501 on TLS/HTTP-2/HTTP-3 fronts).

Forward every Host and path on origin_port to 127.0.0.1:target_port.

The one rule that ignores the Host header: use it for a plain port-to-port hop. A cwist_proxy_route() origin on the same port takes precedence over it at equal prefix length. The port is TLS when the named origins are https:// or, with no named origins, when a certificate is configured.

cwist_error_t cwist_proxy_route ( const char *  origin,
const char *  origin_route,

)

Forward requests for an origin route to a target route.

Parameters
originThe origin as the browser address bar shows it: "http://api.example.com:8080" or "https://api.example.com" (port defaults to 80/443 by scheme). Scheme and host are required. The proxy listens on the port on every interface and serves a request only when its Host names this origin exactly (host case-insensitive, port explicit or the scheme default), so "http://localhost:8080" does not answer for "127.0.0.1:8080". Other Hosts get 421 Misdirected Request.
origin_routePath prefix on the origin, e.g. "/api". It matches "/api" and "/api/..." but not "/apix". "/" matches every path.
targetUpstream as "http://host:port", "https://host:port" or "host:port" (http). No path, query or userinfo.
target_routePath prefix that replaces origin_route upstream, e.g. "/v1" sends "/api/users?x=1" to "/v1/users?x=1".
Returns
err_i16 0 on success; -1 on invalid arguments, a duplicate rule, an http:// and https:// origin on the same port, allocation failure, or after cwist_proxy_listen() has started.

The longest matching origin_route wins; an origin that matches but has no matching route answers 404. All origins currently share one scheme: the listeners are either all TLS or all cleartext.
