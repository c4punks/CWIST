Detailed Description

HTML page and fragment responses for HTML-over-the-wire handlers.

A handler builds the content it owns (usually with cwist_html_component_t) and lets these helpers decide how to answer: a full document on a normal navigation, only the fragment when the client asked for one. Out-of-band elements and redirects follow the same request-driven switch, so the same route works with and without client-side script (progressive enhancement).

Fragment requests are recognised by the request headers that fragment- swapping clients already send: HX-Request: true (htmx) and Turbo-Frame (Hotwire Turbo frames). Nothing here requires either library.

Append an out-of-band element to a fragment response.

For a fragment request the element is rendered after the current body with hx-swap-oob="true" (unless the caller already set hx-swap-oob), so the client replaces the element with the same id elsewhere on the page. For a full-page request it is dropped: the page being sent already contains that region. Clients that do not implement out-of-band swaps ignore the extra element.

Call it after the main content has been set.

Parameters
reqRequest being answered.
resResponse whose body receives the element.
elElement to append; must carry a non-empty id attribute. Always consumed, including on failure.
Returns
0 when appended or deliberately dropped, -1 on invalid arguments (a missing id included) or allocation failure.

Append an out-of-band element to a fragment response.

The element must have an "id" attribute. When the client requested a full page the element is dropped (a full page already contains the region) and success is reported. Otherwise an hx-swap-oob="true" attribute is added if missing and the element is rendered and appended to the body. Takes ownership of el in all cases.

Redirect in a way both plain navigation and fragment clients follow.

An htmx request (HX-Request: true) gets 200 with HX-Redirect: <location>, because a script-driven request follows a 3xx itself and would swap the target page into the fragment slot. Every other request, Turbo frames included, gets 303 See Other with Location, which also turns a form POST into a GET. The body is emptied in both cases.

Parameters
reqRequest being answered.
resResponse to fill.
locationTarget URL; must be non-empty and free of control characters (CR/LF would split the response).
Returns
0 on success, -1 on invalid arguments or allocation failure.

Redirect in a way both plain navigation and fragment clients follow.

For htmx requests (HX-Request: true) the status stays 200 and the target is sent via the HX-Redirect header; otherwise a 303 See Other response with a Location header is produced. Any previous Location and HX-Redirect headers are removed and the body is cleared.

Parameters
reqRequest used to decide between htmx and regular redirects.
resResponse to modify.
locationRedirect target; must be non-empty and free of control bytes.
Returns
0 on success, -1 if the response cannot hold HTML, the location is invalid, or header/body updates fail.

Answer with a fragment or a full page, depending on the request.

A fragment request gets content alone. Any other request gets a document: content wrapped by layout when one is given (the layout component receives content as its single child, see cwist_html_component_instantiate()), or content itself as the document root otherwise. Both answers carry Vary: CWIST_HTML_FRAGMENT_VARY.

Answer with a fragment or a full page, depending on the request.

When the client requested a fragment, content is rendered alone; otherwise it is embedded into the layout component (or rendered as a full document when no layout is given). Takes ownership of content in all cases. On success a Vary header for fragment-negotiation is appended.
