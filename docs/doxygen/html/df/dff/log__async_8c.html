Detailed Description

Opt-in background writer for log lines (cwist_log_async_start()).

Each output fd (stdout, stderr) has one byte ring. A caller formats its line on its own stack, copies it into the ring under one mutex and returns; a single writer thread write()s the rings to their fds. Callers never make a syscall on the request path, and lines stay whole and in submission order per fd.

A full ring makes the caller wait for space, so no line is dropped. A line larger than the ring, or any line while the writer is not running, is refused and the caller writes it synchronously as before.

fork(): the child keeps the rings' memory but not the writer thread. Its copy of the parent's queued bytes is discarded (the parent writes them) and a writer is started on the child's first line.

◆ cwist_log_async_start()

bool cwist_log_async_start ( size_t  buffer_bytes)

Start writing log lines from a background thread.

Start the background log writer.

Parameters
buffer_bytesRing size per stream (stdout and stderr); 0 selects 256 KiB.
Returns
true when async logging is active (also when it already was), false when memory or the thread could not be had; logging then stays synchronous.
Note
Covers cwist_logger_* and the built-in access-log middleware. Lines queued at exit() are written by an atexit hook; call cwist_log_async_stop() or cwist_log_async_flush() before _exit() or a crash-prone section if the last lines matter.
