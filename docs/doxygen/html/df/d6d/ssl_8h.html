Detailed Description

mbedTLS TLS backend: OpenSSL-shaped seam over the CWIST TLS subset.

This header (and its siblings in this directory) is the CWIST TLS backend seam. When the library is built with CWIST_TLS=mbedtls the Makefile puts this directory on the include path instead of lib/boringssl/include, so every call site - public headers, https.c, http2.c, grpc_client.c - keeps its <openssl/ssl.h> include and its SSL_* call shape, but compiles against the declarations below. Each OpenSSL-flavoured name is a macro alias for a cwist_mtls_* function genuinely implemented on mbedTLS (mbedtls_ssl_*) in src/security/tls/backend_mbedtls.c, so the produced archive carries no BoringSSL object or symbol.

Design notes:

  • SSL / SSL_CTX / SSL_METHOD are opaque handles; no public struct changes, so the API baseline is untouched.
  • SSL_new() takes a reference on the SSL_CTX exactly like BoringSSL: the cwist_https_reload_context() hot-swap contract (old SSL_CTX stays alive until its last connection drains) is preserved by an internal refcount.
  • Error codes mirror BoringSSL's SSL_ERROR_* values; SSL_get_error() reports the outcome of the last operation on that connection.
  • Only the subset CWIST actually uses is provided. Anything outside it (X509 inspection, PKCS#7, ASN.1, DTLS) stays BoringSSL-only; the modules that need it (AIA chain autoload, ECH, WebRTC, HTTP/3) are compiled out or degraded when CWIST_TLS=mbedtls, as documented in the Makefile and docs/performance/tls-backends.md.
