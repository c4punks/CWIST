Detailed Description

CWIST over lwIP's raw TCP API; see <cwist/sys/port/lwip.h>.

Not part of libcwist: the firmware compiles this file next to lwIP so it picks up the firmware's lwipopts.h. Uses only public CWIST API (parse, dispatch, serialize), which keeps it independent of the socket runtime.

One connection runs one exchange at a time:

recv -> rx buffer -> frame (Content-Length) -> parse -> dispatch -> serialize into tx -> tcp_write as tcp_sndbuf allows -> tcp_sent acks drain tx -> next pipelined request or close

Connections, their request buffers and their response buffers come from a single static pool allocated once at listen time (max_conns slots of sizeof(conn) + rx_buffer_bytes + tx_buffer_bytes); accept/close move slots between the free list and the active list without touching the heap.

tx is written without TCP_WRITE_FLAG_COPY, so lwIP references it until the peer acknowledges. A response that fits the buffer is copied into it and the response object is destroyed immediately; a larger response keeps its object alive and is streamed through the buffer one chunk at a time as acknowledgements arrive.

With CWIST_LWIP_TLS and cfg.tls set, mbedTLS sits between the pcb and the same rx/tx buffers: received ciphertext queues in tin and is decrypted into rx by the pump; tx goes through mbedtls_ssl_write, whose records are copied into lwIP (TCP_WRITE_FLAG_COPY) by the BIO, so the next response can reuse the storage as soon as mbedTLS has taken all of it. The next pipelined request is then picked up from tcp_sent, as on the plaintext path.
