◆ cwist_https_park()

bool cwist_https_park ( cwist_https_connection *  conn,
uint64_t  idle_ms,
cwist_https_park_class  cls 
)

Hand an idle connection back to the HTTPS pool's park set.

— API Functions —

A pool thread that has nothing to read on conn calls this instead of blocking in poll(): the connection is watched by one epoll thread and resubmitted to the pool when bytes arrive, so an idle keep-alive connection costs memory but no thread. Returns true when the connection was parked; the caller must then return without touching conn again (another pool thread may already be serving it). Returns false when parking is unavailable (full GC, CWIST_HTTPS_PARK=0, shutdown); the caller keeps serving the connection the blocking way.

Parameters
idle_msIdle budget before the class-specific expiry action.

cwist_error_t cwist_https_reload_context ( cwist_https_context *  ctx,
const char *  cert_path,

)

Hot-reload the certificate chain and key of a live HTTPS context.

Builds and fully validates a new SSL_CTX, then atomically swaps it into ctx: established connections and in-progress handshakes keep running on the old SSL_CTX (held alive by BoringSSL reference counting), while new handshakes present the new certificate. The shared session-ticket key is carried over, so session resumption survives the reload.

Safe to call from any thread while listeners are serving.

Parameters
ctxHTTPS context created by cwist_https_init_context*().
cert_pathPath to the new PEM certificate chain.
key_pathPath to the new PEM private key.
appApplication context for the PQC layer (may be NULL).
Returns
err.error.err_i16 == 0 on success; on failure the old certificate keeps serving.

Hot-reload the certificate chain and key of a live HTTPS context.

Parameters
ctxLive HTTPS context whose SSL_CTX is replaced.
cert_pathPath to the new PEM certificate chain.
key_pathPath to the new PEM private key.
appApplication context for the PQC layer (may be NULL).
Returns
Tagged CWIST error describing success or failure. On failure the previous certificate keeps serving.

The new SSL_CTX is fully built and validated before the swap. Connections established (or handshaking) on the old SSL_CTX keep it alive through BoringSSL's reference counting and finish on the old certificate; new handshakes use the new one. The shared session-ticket key is carried over unchanged, so tickets issued before the reload still resume afterwards (see docs/decisions/0002-tls-hot-reload.md).

cwist_error_t cwist_https_send_response ( cwist_https_connection *  conn,

Serialize an HTTP response and send it over an active TLS connection.

Serialize an HTTP response and send it over the SSL connection. Streams the header block and body separately (zero-copy; no intermediate serialization blob) and supports pointer bodies and file streams. CWIST_HTTPS_WRITE_TIMEOUT_MS bounds the complete response write (default: 300000). A write also stops after 30 seconds without progress or promptly after application/pool shutdown.

Zero-copy counterpart of the plaintext send path: the header block is serialized into a stack buffer and written first, then the body is streamed straight from its origin (pointer body, sstring, or file stream) instead of materializing one contiguous heap blob.

Parameters
connActive HTTPS connection wrapper.
resResponse object to serialize.
Returns
Tagged CWIST error describing success or failure.
