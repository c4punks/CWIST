◆ cwist_conn_pending_t

typedef struct cwist_conn_pending cwist_conn_pending_t

One thread's list of tracked connection handles, plus enough to let the process-exit sweep (cwist_conn_registry_sweep_all(), running on whichever thread happens to call exit()/return from main) safely race against this same thread's own TLS-destructor sweep (running if this thread happens to exit around the same time): lock serializes the two, swept makes a second attempt (by either path) a no-op instead of double-closing everything.

void cwist_conn_registry_flush ( void  )

Close every handle this thread still tracks, right now.

Sweep (close) everything still on the calling thread's pending-sweep list right now, without waiting for thread exit. Analogous to cwist_gc_scope_flush() but for connections.

Unlike the sweeps, the list stays usable afterwards: entries are closed and cleared but the list is not marked swept, so later tracks still work.

void cwist_conn_registry_sweep_all ( void  )

Close every still-registered thread's tracked handles.

Sweep every thread's pending-sweep list right now. This is what the process-exit (atexit) hook calls; exposed directly for testing, or for callers that want a deterministic sweep point earlier than actual process exit (e.g. cwist_app_destroy()).

Intended for process-exit paths; each list is closed at most once even if a thread's TLS destructor sweep races with this call.

◆ cwist_full_gc()

void cwist_full_gc ( bool  enable)

Claim full-GC mode permanently, exactly once, then harden the toggle.

Enable or disable full-GC mode process-wide.

The first caller stores enable into the guard page, marks the page locked, and mprotect()s it read-only; every later call is a silent no-op. Fails safe (no-op) when the guard page was never mapped. Also toggles auto-rotation on the process-wide full-GC instance.

Parameters
enabletrue to enable full-GC mode, false to claim-and-disable.
