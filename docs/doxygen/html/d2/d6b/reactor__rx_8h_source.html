1/* Internal RX-uring receive path (issue #179).
2 *
3 * The C1M async HTTP server normally waits for readability with a one-shot
4 * POLL_ADD and then drains the fd with recv(). When the reactor runs a real
5 * io_uring ring, the receive wait can instead be an IORING_OP_RECV whose
6 * completion IS the readiness signal: one SQE replaces the POLL+recv pair
7 * and rides the existing deferred-SQE batch, so no extra io_uring_enter is
8 * paid beyond what the run loop already spends.
9 *
10 * SQE namespace: the run loop dispatches on cqe->user_data, historically an
11 * ev_ctx pointer. RECV SQEs tag the low bit of user_data and carry the
12 * connection pointer in the remaining bits:
13 *
14 * user_data = (uint64_t)conn | 1
15 *
16 * ev_ctx pointers come from cwist_alloc (malloc-backed, so at least
17 * max_align_t aligned) and can never carry the tag bit; reactor.c asserts
18 * this when arming. Multishot-accept slots (see the bottom of this header)
19 * tag bit 1 instead, so the run loop can tell all three apart.
20 *
21 * RX-epoll: on an epoll reactor (no io_uring ring, e.g. under a seccomp
22 * profile that blocks it) the same contract is served without SQEs. The fd
23 * stays registered edge-triggered (no EPOLLONESHOT) with user_data
24 * fd << 1 | 1, and on readiness the reactor itself recv()s into the armed
25 * buffer and reports the result through the same completion handler. A
26 * steady keep-alive request then costs one recv and one send, where the
27 * one-shot path also paid an epoll_ctl re-arm. Epoll arms are accepted on
28 * the run thread only; elsewhere cwist_reactor_recv_arm returns false and the
29 * caller's POLL fallback re-arms from the run thread. Any cwist_reactor_add,
30 * _mod or _del of the fd takes it back to the one-shot path. -EAGAIN is
31 * never reported: the receive stays armed until bytes, EOF or an error.
32 *
33 * This header is private to the build (src/sys/io); it is not installed.
34 * Everything compiles to no-ops on non-Linux so callers need no ifdefs
35 * beyond cheap inline checks. */

75/* Arm one IORING_OP_RECV on the reactor ring. The SQE references

78 * At most one RECV per connection at a time. When the latency probe is
79 * enabled, *armed_ns (if non-NULL) receives the arm timestamp so the caller
80 * can compute queue delay. Run-thread calls during dispatch defer into the

93/* --- Multishot accept (issue #406) -----------------------------------------
94 * The listen socket's accept can ride one IORING_OP_ACCEPT with
95 * IORING_ACCEPT_MULTISHOT instead of a one-shot POLL + accept4 drain loop:
96 * each completion IS an accepted connection (SOCK_CLOEXEC|SOCK_NONBLOCK
97 * already set). Accept slots tag bit 1 of user_data (the RX path uses bit
98 * 0); both live outside the ev_ctx namespace, whose slots are malloc-aligned.
99 *
100 * The slot is persistent, unlike the one-shot ev_ctx slots: it survives
101 * across completions until the multishot accept terminates (completion
102 * without IORING_CQE_F_MORE) or the reactor is destroyed. */
103
104/* Completion handler for multishot accepts. fd >= 0 is a freshly accepted
105 * socket (CLOEXEC+NONBLOCK set). A negative fd is -errno and is delivered
106 * exactly once, when the accept terminates: unsupported opcode on an old
107 * kernel (-EINVAL), listener error, or teardown. The caller should resume
108 * the one-shot POLL accept loop; the reactor has already freed the slot when
109 * the callback returns. Runs on the reactor owner thread while dispatching. */
110typedef void (*cwist_accept_cb_t)(void *ctx, int fd);

112/* Arm one multishot accept on the reactor ring. At most one per listen fd.

115 * before cwist_reactor_run() or from the run thread. */
116bool cwist_reactor_accept_arm(cwist_reactor_t *reactor, int listen_fd, cwist_accept_cb_t cb,
