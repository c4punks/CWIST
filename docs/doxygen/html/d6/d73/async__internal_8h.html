◆ cwist_async_dispatch_take()

struct cwist_async * cwist_async_dispatch_take ( cwist_http_response *  res)

Dispatch side of the handoff: return the handle cwist_async_defer() created for res on this thread, or NULL if the handler did not defer it, and forget it. Dispatch calls this right after the handler returns and uses the result instead of res->deferred/res->async, which a producer can reach and overwrite before the ack. A mismatch between the two is reported (and aborts under CWIST_ASYNC_STRICT=1).

◆ cwist_async_https_take_deferred()

bool cwist_async_https_take_deferred ( void  )

Return whether cwist_async_defer() handed an HTTP/1.1 HTTPS connection to its completion on this thread since the last call, and clear the flag (deferring an h2 stream leaves the conn with the h2 loop). The HTTPS pool worker checks this instead of conn->deferred: once the dispatch ack is published the completion owns the conn and may already have closed or resubmitted it.

◆ cwist_async_res_deferred()

bool cwist_async_res_deferred ( const cwist_http_response *  res)

Return whether res is deferred as seen from this thread: either cwist_async_defer() deferred it here and dispatch has not taken it yet, or res->deferred is set. Middleware uses this so a producer that clears res->deferred early cannot make the dispatch thread touch the response.

Close an async connection whose owning worker pool is gone.

Close a deferred connection whose worker reactor is gone: close client_fd and release conn without touching the worker load counters.

Post a reactor node only while the captured generation is current.

Post node to reactor only while the reactor still belongs to generation gen. Returns false, without posting, once the pool that owned it has been destroyed.

Counts the caller in g_reactor_posters around the generation check and the post so cwist_http_pool_destroy() cannot free the reactor in between.
