◆ cwist_grpc_stream_recv()

int cwist_grpc_stream_recv ( cwist_grpc_stream *  stream,
cwist_grpc_message *  out 
)

Receive the next inbound message on a stream.

Blocking receive for streaming handlers on the HTTP/2 transport path. Returns 1 and fills out when a message arrived, 0 on client half-close (END_STREAM), and -1 when the call was cancelled (client RST_STREAM, deadline expiry, or transport error). On the buffered (in-process) path this pops from the pre-decoded message array. out->data stays valid until the next recv on the same stream.

Buffered path: pops the next pre-decoded message, enforcing the deadline first. Transport path: blocks on the session queue until a message arrives, the call is cancelled, EOF is reached, or the deadline expires.

Parameters
streamStream to read from; may be NULL.
outReceives the message (borrowed pointer valid until the next recv on this stream).
Return values
1A message was delivered.
0End of stream (no more messages).
-1NULL argument, cancellation, or deadline exceeded (stream status set to DEADLINE_EXCEEDED in the latter case).

Advertise a server-side retry pushback hint to the client.

gRFC A6 server pushback: attach "grpc-retry-pushback-ms" to the response trailers. A non-negative ms asks the client to wait that long before retrying; a negative value asks it not to retry at all. For unary handlers the same effect is available by adding a "grpc-retry-pushback-ms" header to the response.

Records the hint on the stream; on the buffered path it is also emitted as the grpc-retry-pushback-ms header for the HTTP/2 layer to move into the trailers.

Parameters
streamStream to annotate; may be NULL (no-op).
msRetry delay hint in milliseconds.
