◆ cwist_websocket_receive()

cwist_ws_frame * cwist_websocket_receive ( cwist_websocket *  ws)

Receive a frame, blocking until data arrives or the socket closes.

Returns
NULL on error or if the connection was closed.

Receive a frame, blocking until data arrives or the socket closes.

Transparently reassembles fragmented messages (RFC 6455 section 5.4): frames with FIN=0 are buffered internally and the function blocks until the final FIN=1 frame arrives, at which point the fully-assembled payload is returned as a single frame. Control frames (CLOSE, PING, PONG) are always FIN=1 and are delivered immediately even when a fragmented data message is in progress.

Client frames are required to be masked by RFC 6455, so unmasked payloads are rejected. The returned payload is null-terminated for convenience.

Parameters
wsWebSocket connection wrapper returned by cwist_websocket_upgrade().
Returns
Newly allocated frame, or NULL when the connection is closed or invalid.

Send one TEXT or BINARY message as RFC 6455 fragments.

The application chooses the fragment boundaries. The first fragment is sent with opcode and FIN clear, the middle fragments as CONTINUATION frames, and the last fragment as a CONTINUATION frame with FIN set. One fragment is sent as a single FIN frame, and zero fragments send one empty message. Fragments may be empty. Text fragments may split a UTF-8 sequence; only the reassembled message must be valid UTF-8.

All arguments are checked before anything is written. The frames are written back to back, so no control frame from this connection can land inside the message. If a write fails part way, the peer holds an unfinished message and the connection should be closed.

Parameters
wsWebSocket connection.
opcodeCWIST_WS_FRAME_TEXT or CWIST_WS_FRAME_BINARY.
fragmentsArray of count fragments; may be NULL when count is 0.
countNumber of fragments.
Returns
0 on success, -1 on invalid arguments or a socket write failure.

Splits data into chunks of chunk_payload_size (or smaller for the final chunk), prefixes each chunk with the CWIST sequence header, and sends every chunk as an independent binary frame. The peer can reassemble the original payload even when frames arrive out of order.
