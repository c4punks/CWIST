# Mux 알고리즘 참고 자료

이 문서는 `src/net/http/mux.c`에서 쓰는 해싱과 인덱싱 기법의 역사적, 수학적 배경을 남겨 둡니다.
아이디어는 라우터 구현으로 이어졌지만, **프로덕션 소스 코드**는 이후 유지보수자가 문화적 맥락이
아니라 제어 로직에 집중할 수 있도록 표준 시스템 프로그래밍 용어를 쓰도록 리팩터링되었습니다.

---

## 1. 낙서 마방진 (洛書)

**개념**
고대 중국 수학에 기록되고, 이후 조선의 학자 **최석정(崔錫鼎, 1646-1715)**이 『구수략(九數略)』에서
깊이 연구한 3x3 마방진입니다. 마방진에서는 모든 행, 열, 대각선의 합이 같은 상수입니다 (낙서는
15). 최석정은 이를 더 큰 차수로 확장하고 그 조합론적 성질을 탐구했습니다.

**mux.c에서의 적용**
마방진은 라우트 시그니처를 작은 정수 좌표로 대응시키는 결정론적 조회 테이블로 쓰였습니다. 행과
열의 합이 같다는 성질은 라우트 수가 늘어나도 버킷 부하를 고르게 유지하려는 의도였습니다.

**현재 코드 이름**
- `CWIST_ROUTING_HASH_SLOT` (이전 `CWIST_LO_SHU`)
- `cwist_routing_hash_slot()` (이전 `cwist_magic_square_coord()`)

## 2. 직교 라틴 방진 순열

**개념**
라틴 방진과 그 직교 쌍은 **최석정**이 『구수략(九數略)』에서, 이후 **홍정하(洪正夏)**가
『구일집(九一集)』에서 다룬, 한국 고전 수학의 조합 설계입니다. 두 라틴 방진은 모든 기호의 순서쌍이
정확히 한 번씩 나타날 때 직교합니다. 이 구조에 대한 최석정의 연구는 직교 라틴 방진에 대한 유럽의
공식적인 연구보다 한 세기 이상 앞섭니다.

**mux.c에서의 적용**
4x4 직교 테이블 두 개(`MUX_PERM_TABLE_A` / `MUX_PERM_TABLE_B`)로 라우트 바이트와 그 세그먼트
인덱스를 4비트 니블 하나로 접었습니다. 이 니블은 세그먼트 혼합 중에 128비트 라우트 시그니처를
교란합니다.

**현재 코드 이름**
- `MUX_PERM_TABLE_A` (이전 `NAM_LS_PRIMARY`)
- `MUX_PERM_TABLE_B` (이전 `NAM_LS_SECONDARY`)
- `mux_byte_permute()` (이전 `nam_latin_merge()`)

## 3. 계수 행렬과 선형 연립방정식 풀이

**개념**
『승제개방법(乘除開方法)』은 비율을 조정하고 정규화하는 조선 시대의 기법입니다. 여기서 쓰는
행렬은 미지의 가중치 세 개에 대해 풀 수 있는 선형 연립방정식을 만드는 3x3 고정 계수 행렬입니다.

**mux.c에서의 적용**
행렬(`MUX_COEFF_MATRIX`)과 가우스 소거 풀이기(`mux_solve_linear3()`)가 라우트 시그니처의 상위,
하위 64비트 절반에서 가중치 세 개를 끌어냅니다. 그 가중치는 최종 버킷 인덱스에 섞입니다.

**현재 코드 이름**
- `MUX_COEFF_MATRIX` (이전 `JOSEON_RATIO_MATRIX`)
- `mux_solve_linear3()` (이전 `cwist_dawonsul_solve3()`)
- `mux_derive_coeffs()` (이전 `cwist_jungseung_coeffs()`)

## 4. 반복적인 크기 정제

**개념**
알카시(al-Kāshī, 15세기 천문학자이자 수학자)는 반복적인 근 찾기 방법을 널리 알렸습니다. 여기서
쓰는 단계는 두 번 반복하는 뉴턴-랩슨 방식의 제곱근 정제입니다.

**mux.c에서의 적용**
최종 혼합 단계에 넣기 전에 중간 크기 추정값을 정제합니다. 서로 다른 버킷 크기 전반에서 비트
확산을 개선합니다.

**현재 코드 이름**
- `mux_refine_magnitude()` (이전 `cwist_al_kashi_refine()`)

---

## 5. 단일 단계 선형 외삽

**개념**
상미분방정식에 대한 오일러 방법은 현재 기울기에 작은 단계 크기를 곱해 더함으로써 다음 상태를
예측합니다.

**mux.c에서의 적용**
정제된 크기와 시그니처 바이트 차이에서 얻은 기울기로 다음 해시 혼합 상태를 예측합니다. 경로가
조금 바뀌어도 버킷 인덱스가 안정적으로 유지됩니다.

**현재 코드 이름**
- `mux_predict_state()` (이전 `cwist_euler_predict()`)

## 이름을 바꾼 이유

위의 수학적 아이디어는 해시 분포 설계에 유효하지만, 역사적 인물 이름, 시대 이름, 문화적 개념을
프로덕션 식별자에 직접 넣으면 이후 엔지니어에게 불필요한 인지 부담이 생깁니다. 리팩터링한 이름은
아이디어가 **어디서 왔는지**가 아니라 코드가 **무엇을 하는지**(라우팅 해시 슬롯, 바이트 순열,
선형 풀이기, 크기 정제, 상태 예측)를 설명합니다.

원래 수학에 대해 더 알고 싶다면 조합론, 수치 해석, 선형대수 분야의 문헌을 참고하세요.
