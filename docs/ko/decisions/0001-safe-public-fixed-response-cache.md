# ADR-0001: 명시적인 공개 FIXED 계약으로 HTTP 응답 캐싱 복원하기

- **상태:** 메인테이너 검토를 위해 제안됨. 구현되거나 릴리스되지 않음.
- **날짜:** 2026-09-13
- **범위:** classic과 C1M 모드의 평문 HTTP/1.
- **소스 기준선:** `7e19b461c5772f4e46e7d58fb96827bbb954cf97`.
- **관련:** [이슈 #25](https://github.com/c4punks/CWIST/issues/25), [PR #84](https://github.com/c4punks/CWIST/pull/84).

## 배경

기존 `CWIST_ENDPOINT_FIXED` 문서는 첫 요청 이후의 RAM 캐싱을 약속합니다. 공개 TCP 관찰은 그 약속과 어긋납니다. classic과 C1M 두 모드 모두에서 FIXED 요청 16개가 핸들러를 16번 호출했습니다. 관찰에는 keep-alive 요청 여덟 개와 새 연결 여덟 개, DYNAMIC 대조군, 독립적으로 미리 넣어 둔 캐시 응답이 포함되었습니다. 이 실험에서는 지연 시간 기반 적응 학습을 억제했습니다. 이는 P99.999에 대한 기여가 아니라 채움 실패를 확립합니다.

두 가지 순서 결함이 실패를 설명합니다. 공통 서빙 함수가 라우팅이 엔드포인트 옵션을 지정하기 전에 그 값을 읽고, C1M 분기는 학습 블록 전에 반환합니다. 그 블록만 옮기는 것은 안전하지 않습니다.

- 기존 캐시 히트는 인가를 포함한 라우팅과 미들웨어보다 앞서 일어납니다.
- 파싱된 캐시 키는 쿼리와 다른 표현 구분을 빠뜨립니다. classic의 원시 지름길은 키와 프레이밍 동작이 다릅니다.
- 전체 와이어 blob은 첫 응답의 연결 헤더를 보존합니다. 일부 히트는 확인하지 않는 `send` 한 번을 쓰고, classic 조회는 이미 고정이 풀린 포인터를 반환합니다.
- 일반 전송은 전송 후 학습이 읽기 전에 관리형 포인터 본문을 해제할 수 있습니다.
- 문자열화 도우미가 NUL로 끝나지 않는 헤더 범위를 C 문자열로 다룹니다. PR #84가 그 독립적인 결함을 고치지만, 캐시 재생을 안전하게 만들지는 않습니다.

네이티브 백엔드/스레드 선별 시험은 보편적인 런타임 기본값을 확립하지도, 원래의 꼬리 지연 문제를 해결하지도 못했습니다. 캐시 미스가 성능을 깎더라도 올바른 응답은 필수입니다.

## 결정

제한된 공개, 요청 불변 표현 캐시를 위해, 별도 이름의 옵트인(잠정적으로 `CWIST_ENDPOINT_PUBLIC_FIXED`)을 도입합니다. 이 심볼은 기존 API가 아니라 제안된 API입니다. 자체적인 단일 플래그 비트를 씁니다. 현재 `cwist_endpoint_has` 도우미는 주어진 비트 중 **아무거나** 있는지 검사하므로, 복합 마스크를 모든 비트가 필요한 것으로 착각하면 안 됩니다.

이 옵트인은 핸들러가 허용된 프로필 안에서 인가, 개인화, 요청별로 꼭 필요한 부수 효과, 요청에 따른 선택을 하지 않는다는 애플리케이션 작성자의 단언입니다. 프레임워크는 함수 포인터, 자격 증명의 부재, 이전에 성공한 응답으로부터 그 단언을 추론할 수 없습니다. 기존 FIXED 선언이 이 더 강한 계약으로 조용히 승격되지는 않습니다.

### 1. 하나의 파싱된 자격 경계

classic과 C1M 모두 캐시에 접근하기 전에 요청 전체를 파싱하고 검증해야 합니다. 일반 디스패치와 같은 라우팅 권한으로 현재의 정확한 라우트를 결정합니다. classic의 대체 원시 캐시 진입 경로는 제거합니다. 그 경로가 정책을 우회하는 길로 남아서는 안 됩니다.

첫 프로필은 다음만 허용합니다.

- 새 옵트인을 명시적으로 단, 파라미터 없는 정확한 라우트에 대한 평문 HTTP/1.1 GET. FILE이나 충돌하는 옵션은 없어야 함;
- 설정된 미들웨어가 없는 애플리케이션. 그렇지 않으면 미들웨어의 핸들러 전후 작업을 모두 포함해 매 요청마다 일반 디스패치를 실행;
- 비어 있지 않은 쿼리, 본문, 전송 코딩, Expect, 업그레이드, 세션이나 기타 인증 컨텍스트가 없을 것;
- 유효한 Host 헤더 하나. 받아들인 정확한 값을 키에 포함;
- 요청 헤더는 Host, User-Agent, `Accept: */*`, 일반적인 keep-alive/close Connection 의미로 제한. 알 수 없는 헤더, 중복 인스턴스, 자격 증명, 쿠키, 조건부/범위 요청, 캐시 지시어, 인코딩 협상은 안전한 미스.

이 프로필에서 빈 쿼리는 쿼리가 없는 것과 명시적으로 동등합니다. 현재 요청 모델은 쿼리 구분자가 있었는지를 별도 비트로 보존하지 않습니다. 구현은 길이가 0인 쿼리가 구분자의 부재를 증명한다고 가장하면 안 됩니다. 그 구분이 필요한 이후 프로필은 파싱 중에 그것을 보존해야 합니다.

작성자 계약은 User-Agent, 클라이언트 주소, 시간, 연결 식별자와 무관할 것을 요구합니다. Host와 라우트 식별자는 별도의 키 차원으로 남습니다. 멤버십과 값 검사는 조회 도우미가 반환하는 첫 값만이 아니라 모든 헤더 노드를 대소문자 구분 없이 확인해야 합니다. 잘못되었거나 지원하지 않는 값은 최선의 캐시 히트가 아니라 항상 일반 디스패치로 이어집니다.

### 2. 와이어 응답이 아니라 표현을 캐시하기

소유한 바이너리 본문, 검증된 선택적 Content-Type, 권위 있는 라우트/키 식별자를 저장합니다. 일반적인 keep-alive 능력, 기본 HTTP/1.1 버전, 표준 이유 문구를 가진 완전한 동기 200 응답만 자격이 있습니다. 연기된, 업그레이드된, 파일 스트림, 부분/200이 아닌, 연결을 닫는 응답은 거부합니다. 헤더 목록 밖에 있는 연결 의존적 덮어쓰기(`alt_svc`, 사용자 지정 버전/상태 텍스트 필드 등)도 거부합니다. 제한된 크기의 단일 Content-Type 외의 응답 헤더가 있으면 첫 프로필에서는 자격이 없습니다. 이는 Set-Cookie, Vary, 캐시 제어 정책, Date, Alt-Svc, 프레이밍 덮어쓰기를 부분적으로 구현하는 대신 의도적으로 제외하는 것입니다.

히트는 현재 요청에 대한 일반 응답을 만듭니다. Content-Length와 연결/종료 동작을 새로 계산하고, 기존의 일반 classic 송신기나 병합/대기(parked) C1M 송신기를 씁니다. 캐시 저장소를 단발성 원시 `send`로 보내면 절대 안 됩니다. 전송 계층이 소유하는 헤더는 다시 만들고, 첫 요청의 닫기 결정을 재생하지 마세요.

동기 디스패치와 그 연기 응답 가드 이후, 그러나 전송이 포인터 본문을 소비하기 전에 제한된 크기의 소유 스냅숏을 잡습니다. 게시는 네트워크 전달의 증명이 아니라 자격 있는 표현을 성공적으로 만들었다는 뜻입니다. 할당이나 삽입이 실패하면 원래 응답을 보내는 것으로 돌아가야 합니다. 히트 재구성이 실패하면 캐시된 바이트를 하나도 내보내기 전에 일반 디스패치로 돌아갑니다.

### 3. 소유권, 출처, 용량 격리하기

제한된 조회/갱신 임계 구역으로 보호되는, 캐시가 소유한 불변 항목을 씁니다. 항목이 보호되는 동안 히트를 요청 소유 저장소로 복사한 뒤, 전송 전에 캐시 락을 놓습니다. 캐시 락, 스레드 로컬 에포크 고정, 빌린 본문 포인터 어느 것도 블로킹 전송, 리액터 대기, 연기된 완료, 응답 파괴를 넘어가지 않습니다.

캐시 할당은 요청 아레나나 스레드 GC 수명이 아니라 애플리케이션 캐시 수명을 가져야 합니다. 복사본과 관리형 본문 해제 훅은 full GC를 켜든 끄든 정확히 한 번의 소유권을 유지해야 합니다. 캐시 파괴는 워커/연결 종료 이후에 일어나며 모든 항목을 해제합니다.

초기 한도는 본문당 64 KiB, 복사한 Content-Type 1 KiB, 항목 256개, 워커 프로세스당 계산된 항목/키/본문/메타데이터 저장소 16 MiB이고, 단조 시계 기준 최대 수명은 60초입니다. 이는 측정된 최적값이 아니라 보수적으로 제안한 한도입니다. 계산된 저장소에는 할당자 오버헤드가 빠져 있으며 RSS 보장이 아닙니다. 용량 압박이나 만료 시에는 안전하게 내보내거나 미스로 처리하며, 무제한 큐나 백그라운드 워커를 추가하지 않습니다. 할당 전에 산술을 확인하세요.

현재의 정확한 라우트 식별자, 메서드, 경로, 받아들인 Host 값으로 키를 만듭니다. 예전 휴리스틱이나 수동으로 넣은 전체 와이어 BDR blob을 검증된 표현 항목으로 취급하면 절대 안 됩니다. 라우트와 미들웨어는 서비스 전에 설정되며, 실행 중 동시 라우트 변경은 이 프로필의 범위 밖입니다. 구현은 지원되는 재설정 시 영향받는 항목을 무효화해야 하며, 라우터 자체가 지원하지 못하는 라우트 변경 안전성 주장을 추가해서는 안 됩니다.

### 4. 호환성 변경을 명시하기

권장 이전 방식은 자동 HTTP BDR 조회/학습을 제한된 옵트인 경로로 바꾸는 것입니다. 기존 BDR 저장 API는 애플리케이션에서 계속 쓸 수 있지만, 기존 휴리스틱 또는 수동으로 미리 넣은 와이어 blob은 더 이상 HTTP 라우팅을 자동으로 우회하지 않습니다. 맨 FIXED와 DYNAMIC 라우트는 명시적으로 이전되기 전까지 일반 디스패치를 거칩니다. 그 결과로 잃는 기존 자동 캐시 히트를 문서화하세요.

이것은 메인테이너의 수용과 릴리스 노트가 필요한 의도적인 호환성 변경입니다. 직렬화기 수정 안에 숨겨져 있지 않습니다. 안전하지 않은 기존 빠른 경로를 캐시의 실패 동작으로 노출하지 마세요. 공개 상수 응답임이 입증된 예제와 벤치마크 고정물만 이전하고, 기존 FIXED 비트를 근거로 애플리케이션 라우트를 일괄 변환하지 마세요.

## 검토한 대안

1. **학습을 옮기고 FIXED만 다시 읽기.** 차이가 작지만 우회, 프레이밍, 부분 쓰기, 수명 결함을 활성화합니다. 거부.
2. **기존 FIXED를 공개 불변 핸들러의 증명으로 취급하기.** 새 플래그를 피하지만, 배포된 선언의 계약을 조용히 강화하고 핸들러 내부의 인가가 없음을 증명할 수 없습니다. 기본 이전 방식으로는 거부.
3. **일반적인 공유 HTTP 캐싱 구현하기.** 변형을 인식하는 키, 미들웨어를 보존하는 실행, 검증자, 캐시 지시어, 더 넓은 전송 계층으로 더 많은 사용 사례를 지킬 수 있습니다. 보류: 현재 조사보다 프로토콜과 API 범위가 훨씬 큽니다.
4. **캐싱을 잠든 상태로 두고 스케줄러 경합만 조사하기.** 안전한 단기 대안이며 여전히 유효한 병렬 조사입니다. 입증된 캐시 계약 실패를 고치지는 않습니다.

## 결과

- 지원하지 않는 트래픽은 안전한 미스로 처리됩니다. 캐시 히트율은 기밀성과 올바른 프레이밍보다 뒤입니다.
- 명시적인 이전이 필요하며, 일부 애플리케이션은 기존 자동 히트를 잃습니다. 새 API와 기존 자동 재생 제거는 함께 검토해야 합니다.
- 본문 복사와 동기화가 오버헤드를 더할 수 있습니다. 핸들러 호출 수가 줄었다는 것만으로 꼬리 지연 개선이 확립되지는 않습니다.
- 이 결정은 새 의존성, 리액터 수 기본값, 백엔드 기본값, TLS/H2/H3 캐시 경로, 연기 응답 캐싱, C1M 휴리스틱 캐싱을 도입하지 않습니다.

## 구현과 릴리스 관문

따로 검토할 수 있는 조각으로 구현합니다: 자격/출처와 제한된 저장소, 파싱된 조회와 전송 전 스냅숏과 일반 전송, 공개 API/문서 이전, 그다음 통제된 성능 검증. PR #84는 독립적으로 두고, 병합되었다고 가정하지 말고 실제 선행 리비전을 확인하세요.

릴리스 전에 다음을 요구합니다.

- classic과 C1M에서 첫 미스/두 번째 히트, 정확한 바이너리 본문, keep-alive와 새 연결, Host 분리, DYNAMIC/맨 FIXED 동작을 증명하는 공개 TCP 테스트;
- 중복 헤더, 자격 증명이 없는 미들웨어, 쿼리 변형, 비공개 응답, 에러, 스트리밍, 연기 소유권을 포함해 요청과 응답 가드 각각에 대한 독립적인 부정 테스트;
- 강제 부분 쓰기와 백프레셔, 프레이밍된 본문이 있는 순서 있는 파이프라인, 현재의 닫기/종료 동작, 포인터 본문 정리, 교체/만료와 할당/용량 실패;
- 기존 원시 진입과 미리 넣은 와이어 항목이 새 경계를 우회할 수 없음을 보이는 테스트;
- full-GC 수명 테스트, 새니타이저, 관련 일반/네이티브 스위트, 정확한 후보에 대한 독립적인 정확성/보안 검토;
- 바뀌지 않은 부하와 검증된 런타임 토폴로지에서 같은 러너로 짝지은 기준/후보 측정. 모든 에러와 이상치를 보관. 보정된 P99.999는 처리량과 따로 보고하고, 폐쇄 루프 선별 시험을 고정 비율 프로덕션 SLO와 같은 것으로 보지 말 것.

기밀성, 프레이밍, 소유권 관문 중 해결되지 않은 것이 있으면 캐시를 켜지 마세요. 롤백은 새 자동 캐시를 끄고 일반 디스패치를 유지하며, 안전하지 않은 원시 재생을 다시 켜지 않습니다. 이슈 #25는 성능 목표가 독립적으로 입증될 때까지 열려 있습니다.
