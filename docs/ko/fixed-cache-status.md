# FIXED 엔드포인트 캐싱: 현재 동작

**상태:** 알려진 문서/런타임 불일치. 조사 진행 중.
**관련:** [이슈 #25](https://github.com/c4punks/CWIST/issues/25),
ADR-0001 (초안 PR #85, `CWIST_ENDPOINT_PUBLIC_FIXED`).

## 지금 런타임이 실제로 하는 일

`CWIST_ENDPOINT_FIXED`는 **현재 리비전에서 자동 응답 캐시를 켜지 않습니다**. classic과 C1M 두
모드 모두에서 FIXED 라우트로 오는 모든 요청은 일반 라우팅을 거쳐 핸들러로 디스패치됩니다.
`endpoint_opts.h`와 `docs/api/app.md`의 "응답을 RAM에 캐시하고 첫 히트 이후 즉시 응답한다"는
문구는 의도한 계약을 설명한 것이지 런타임 동작이 아닙니다.

## 근거

공개 TCP 관찰(이슈 #25 참고): FIXED 요청 16개가 핸들러를 16번 호출했습니다. keep-alive 요청
여덟 개와 새 연결 여덟 개였고, DYNAMIC 대조군과 독립적으로 미리 넣어 둔 캐시 응답이 있었으며,
지연 시간 기반 적응 학습은 억제한 상태였습니다. 이는 꼬리 지연에 대한 기여와 무관하게, 캐시가
전혀 채워지거나 사용되지 않는다는 것(채움 실패)을 보여 줍니다.

## 학습 블록을 그냥 옮기지 않는 이유

두 가지 순서 결함이 채움 실패를 설명합니다. 공통 서빙 함수가 라우팅이 엔드포인트 옵션을
지정하기 전에 그 값을 읽고, C1M 분기는 학습 블록 전에 반환합니다. 그 블록만 옮기는 것은 안전하지
않습니다.

- 기존 캐시 히트는 인가를 포함한 라우팅과 미들웨어보다 앞서 일어납니다;
- 파싱된 캐시 키는 쿼리와 다른 표현 구분을 빠뜨리며, classic의 원시 지름길은 키/프레이밍 동작이
  다릅니다;
- 전체 와이어 blob은 첫 응답의 연결 헤더를 그대로 보존합니다. 일부 히트는 확인하지 않는 `send`
  한 번을 쓰고, classic 조회는 이미 고정이 풀린 포인터를 반환합니다;
- 일반 전송은 전송 후 학습이 읽기 전에 관리형 포인터 본문을 해제할 수 있습니다;
- 문자열화 도우미가 NUL로 끝나지 않는 헤더 범위를 C 문자열로 다뤘습니다 (PR #84로 따로
  수정되었지만, 그것이 캐시 재생을 안전하게 만들지는 않습니다).

## 계약이 복원될 때까지의 권장 처리

- FIXED 라우트를 일반 디스패치로 취급하세요. 자동 캐시 히트에 의존하지 말고, HTTP 재생을 기대하며
  전체 와이어 BDR blob을 미리 넣지 마세요.
- 안전한 복원 경로는 ADR-0001(초안 PR #85)입니다. 파싱된 자격 경계, (와이어 blob이 아닌) 표현
  캐싱, 소유권 격리를 갖춘 새로운 명시적 `CWIST_ENDPOINT_PUBLIC_FIXED` 옵트인과 명시적인 호환성
  변경입니다. 어떤 캐시 경로든 구현하거나 켜기 전에 그 ADR을 검토하세요.
- 캐시 미스가 성능을 깎더라도 올바른 응답은 필수입니다. 어떤 성능 목표도 안전하지 않은 원시 재생
  경로를 다시 켜서는 안 됩니다.
