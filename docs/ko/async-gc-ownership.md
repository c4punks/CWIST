# full GC에서의 연기된 HTTP 소유권

연기된(deferred) 교환에는 명시적인 파괴 소유자가 있습니다. 참조 카운트는 CWIST의 스레드 로컬
pending-sweep 목록에서 할당을 빼 주지 않습니다. 게시(publication) 전에 할당한 스레드에서
`cwist_gc_scope_disown`이 실행되어야 합니다. 이 변경은 GC를 끄지도, 할당자를 바꾸지도, 받는
작업의 범위에 할당을 등록하지도 않습니다.

## 인계 순서

1. `cwist_async_defer`는 응답의 async/deferred 필드를 설정하고 핸들을 반환하기 전에, 핸들과
   기존에 소유한 요청/응답 그래프의 소유를 해제(disown)합니다.
2. 동기 미들웨어는 디스패치 스레드에서 후처리 작업을 마칠 수 있습니다.
   `cwist_async_dispatch_ack`는 그래프를 다시 순회해 미들웨어가 되감기는 동안 생긴 할당을
   잡아내고, keep-alive 정책을 갱신한 뒤, 확인(acknowledgement)을 release로 게시합니다. 그
   이후 디스패처는 교환을 건드리면 안 됩니다.
3. 경쟁에서 이긴 완료 생산자는 교환 객체를 변경, 교체, 전송, 파괴하기 **전에** 그 확인을
   acquire합니다. 따라서 확인 시점의 그래프 순회가 응답 변경과 경쟁할 수 없습니다. 경쟁에서
   진 쪽은 호출자가 넘긴 응답을 순회하거나 소유하지 않습니다.
4. `cwist_async_finish`는 리액터에 post하거나 HTTP/2 큐에 들어가기 전에 생산자 스레드에서
   최종 응답의 소유 그래프를 disown합니다. 이는 `respond`, `respond_with`, `abort`와 타임아웃이
   만든 헤더/본문 문자열을 모두 포함합니다.
5. 최종 해제는 기존의 완료/파괴 경로가 계속 책임집니다. 순서는 최종 응답(다를 경우), 원래 응답,
   그다음 요청입니다. 이 순서는 요청 아레나에서 빌린 응답 저장소를 보존합니다. 원래 응답을
   `respond_with`에 넘겨도 중복 파괴가 일어나지 않습니다.

디스패치 스레드에서의 완료는 대기 중인 응답을 차지하고 기록만 할 뿐, 전송하거나 파괴하지
않습니다. 디스패치 확인 전에 완료가 만들어지면, 그 완료는 기록되고 디스패치 확인이 실행을
마무리하거나, 완료가 파괴 전에 디스패치 확인을 기다립니다. 생산자/타이머가 유지하는 참조
규칙은 바뀌지 않습니다.

## 소유권 목록

비공개 `src/net/http/async_gc.h` 순회기는 기존 소멸자를 그대로 따릅니다.

| 소유 자원 | 이전 규칙 |
| --- | --- |
| 요청/응답 껍데기 | 아레나 안에 있지 않으면 disown. 아레나가 NULL이 아니어도 힙으로 대체된 경우를 포함 |
| sstring 저장소 | `owns_storage`일 때만 구조체를, `!borrows_buffer`일 때만 데이터를 disown |
| 헤더 목록 | 각 노드의 키/값을 독립적으로 순회. `!arena_owned`일 때만 노드를 disown |
| 쿼리/경로/flash 맵 | 힙 맵이면 키, 값, 체인 노드, 버킷 배열, 맵을 disown. 아레나 맵에는 힙 대체도 개별 소멸 작업도 없음 |
| 세션 | 세션 모듈이 불투명 세션과 그 데이터 맵을 disown하며, 앱/요청 역참조는 건드리지 않음 |
| 기타 소유 필드 | 요청의 CSRF 토큰과 응답의 Alt-Svc 문자열 |
| 관리되는 포인터 본문 | 정리 콜백이 설치된 경우에만 페이로드 포인터를 disown. 콜백, 컨텍스트, 호출 의미는 그대로 유지 |

아레나는 자체적인 명시적 수명 주기를 가지며 TLS pending 할당이 아닙니다. 아레나가 NULL이
아니라고 해서 모든 하위 항목이 아레나 소유라는 뜻은 **아닙니다**. `scope_disown`은 임의의
페이로드 포인터를 역참조하지 않으며, 추적되지 않는 포인터에 대해서는 아무 일도 하지 않습니다.
NULL과 이미 disown된 할당은 무해합니다.

### 빌린 상태와 외부 상태

순회기는 앱/데이터베이스 포인터, 프로토콜 껍데기, 라우트 미들웨어 상태, 관리되지 않는 포인터
본문, 빌린 sstring 버퍼, 불투명 정리 컨텍스트를 따라가지 않습니다. 호출자는 최종 정리 때까지
그 의존 대상을 살려 두어야 합니다. 정리 컨텍스트가 GC 추적 의존 대상을 소유한다면, 응답을
넘기기 전에 그 대상을 할당한 스레드가 명시적으로 이전해야 합니다. 프레임워크는 불투명한
그래프를 추론하거나 사용자 콜백의 소유권을 바꿀 수 없습니다.

호출자가 제공하는 응답은 `respond_with`를 호출하는 스레드에서 만들거나, 먼저 실제로 할당한
스레드에서 소유 할당을 이전하세요. 나중에 다른 스레드에서 순회해도 원래 스레드의 pending
목록에서 항목을 빼낼 수 없습니다.

## HTTP/2 큐 소유권

HTTP 그래프 순회기가 아니라 큐 모듈이, 명시적으로 참조 카운트되는 큐를 생성 시에 분리하고
완료 노드를 공유 큐에 연결하기 직전에 분리합니다. 생산자는 연결이 비워지기 전에 종료할 수
있고, 유지된 큐는 연결 정리보다 오래 살 수 있습니다. 닫힌 큐는 기존 소멸자 순서로 교환을
버립니다. 노드 할당이 실패해도 이전받은 교환을 소비하고 파괴하므로, 생산자가 소유권을 내려놓은
뒤의 누수를 피합니다.

## 검증과 한계

초기 구현은 런타임 테스트 전에 소스 검토를 거쳤습니다. 커밋
`5b128f1178df374ee5bc3db1aba8f921a6af7d68`에서 Linux ASan/UBSan CI가 GC 켬/끔에 대한 실제 TCP
classic/C1M 행렬을 통과했고, NDEBUG로도 반복했습니다. 이것만으로 크로스 플랫폼 수용을 뜻하지는
않습니다. 이후 macOS 수신 타임아웃 회귀를 전체 네이티브 라이브러리에서 재현했습니다. 종료가
이미 리액터를 멈췄는데, 합쳐진(coalesced) 묶음이 남은 바이트를 대기열에 남겨 두었던 것입니다.
이제 종료를 감지한 flush는 기존 전송 도우미로 그 묶음을 마무리합니다. 이 변경 후 네이티브 TCP
행렬은 여덟 가지 모드 모두에서 통과했습니다. 이것은 절대적인 종료 기한이나 이미 대기 중인
콜백에 대한 보장이 아니며, 도우미는 poll마다의 타임아웃을 유지합니다. 최종 통합 CI는 여전히
필요합니다.

검증 범위에는 완료 전의 생성자 종료나 범위 flush, 힙 헤더/맵/세션/채택된(adopted) 버퍼와 아레나
고갈 시의 대체, 리액터/HTTP2 비우기 전의 생산자 종료, 미들웨어 후처리, 진 쪽의 완료,
타임아웃/abort 경합, 정확히 한 번의 관리형 정리가 포함됩니다. 소유권 목록에서 실행되지 않은
커버리지를 추론하지 마세요.

## 스케줄러와 IO 큐 소유권

스케줄러 껍데기, IO 큐 껍데기, sentinel/제출 노드는 이제 게시 전에 할당한 스레드의 GC 범위를
떠납니다. 기존의 명시적 파괴 경로와 에포크 폐기 경로가 계속 소유자입니다. 큐는 불투명 콜백
인자를 순회하거나 이전하지 않습니다. 추적되는 페이로드는 받는 콜백이 사용하거나 해제하기 전에
호출자가 직접 이전해야 합니다.

`cwist_alloc`과 달리 `cwist_alloc_array`는 추적되지 않는 `cwist_malloc`을 씁니다. 스케줄러 워커
배열은 이미 명시적 수명을 가집니다. 지연 힙은 첫 할당을 포함해 추적되지 않는 `cwist_realloc`을
씁니다. 둘 다 새로운 disown 연산이 필요 없습니다.

macOS/BSD 빌드는 별도의 `kqueue.c` 작업 큐를 선택합니다. 그 큐 껍데기와 kevent 작업 래퍼도
게시 전에 생성자/기증자 범위를 떠납니다. 회귀 테스트는 큐를 멈추기 전에 콜백을 기다리며, 모든
백엔드가 정지 요청 전에 제출된 작업을 비운다고 가정하지 않습니다. 생성자/기증자 종료 순서와
엄격한 GC 범위 검사는 바뀌지 않습니다.

`test_gc_job_handoff`는 큐와 스케줄러 모두에 대해, 사용/파괴 전의 생성자 종료와 소비자가 멈춘
상태에서의 기증자 종료를 실험합니다. 불투명 페이로드 소유권과 지연 힙 증가도 확인합니다. 공통
구현과 kqueue 구현 모두 GC 켬/끔으로 normal/NDEBUG/ASan을 통과했습니다 (구성 요소 실행 12회).
선택된 macOS 백엔드도 전체 라이브러리 normal/NDEBUG 대상을 통과했습니다. 네이티브 ASan은 누수
감지를 끈 채로 실행했으므로, 누수 없음의 증명이나 종료 시 버려지는 대기 콜백에 대한 보장이
아닙니다. 통합 CI는 여전히 필요합니다.
