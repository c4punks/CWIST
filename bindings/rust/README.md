# Rust bindings (experimental)

In-tree Rust bindings for CWIST, v3.8 Phase 2 in `ROADMAP.md` (issue #36).
Experimental: crate version 0.x, not published to crates.io.

| crate | status |
|---|---|
| `cwist-sys` | raw FFI, generated by bindgen from the installed headers |
| `cwist` (safe wrapper) | not yet |

## Building

`cwist-sys` links an installed libcwist through `cwist.pc`, so build and
install CWIST first, then point pkg-config at it:

```sh
make -j"$(nproc)"
make install PREFIX="$PWD/.cwist-prefix"
PKG_CONFIG_PATH="$PWD/.cwist-prefix/lib/pkgconfig" \
    cargo test --manifest-path bindings/rust/Cargo.toml
```

bindgen needs libclang (`libclang-dev` on Debian/Ubuntu; Xcode's on macOS).

## What `cwist-sys` binds

Only what the planned safe wrapper needs, via the allowlist in
`cwist-sys/build.rs`: app lifecycle and routing (including the
`cwist_app_*_ex` routes that carry a user context), in-memory dispatch,
request/response strings and headers, error values, and the `_extern` forms of
`static inline` helpers. `cwist_app`, `cwist_query_map`, `cwist_db`, `cJSON`
and `sqlite3` are opaque.

The struct layouts the bindings mirror are pinned on the C side by
`tests/abi_layout.h`, and bindgen checks the generated layouts against the C
compiler when the crate builds.

## Memory

Rust allocations stay outside `cwist_alloc`: CWIST's full GC and
`CWIST_INTERCEPT_MALLOC` do not apply to Rust code. Buffers CWIST returns
(for example from `cwist_app_dispatch_memory`) are released with `cwist_free`.
A route context registered with a destructor belongs to the app, which calls
the destructor exactly once.
