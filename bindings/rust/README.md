# Rust bindings (experimental)

In-tree Rust bindings for CWIST, v3.8 Phase 2 in `ROADMAP.md` (issue #36).
Experimental: crate version 0.x, not published to crates.io.

| crate | status |
|---|---|
| `cwist-sys` | raw FFI, generated by bindgen from the installed headers |
| `cwist` | safe API: app lifecycle, closure routes, request/response access, advanced FFI (db, scheduler, jwt, siphash, arena, strings) |

## Building

`cwist-sys` links an installed libcwist through `cwist.pc`, so build and
install CWIST first, then point pkg-config at it:

```sh
make -j"$(nproc)"
make install PREFIX="$PWD/.cwist-prefix"
PKG_CONFIG_PATH="$PWD/.cwist-prefix/lib/pkgconfig" \
    cargo test --manifest-path bindings/rust/Cargo.toml
```

bindgen needs libclang (`libclang-dev` on Debian/Ubuntu; Xcode's on macOS).

`cwist.pc` names zstd, brotli, curl and nghttp2 as plain `-l` flags; the build
script finds their directories through their own pkg-config files, as the
CWIST Makefile does (on macOS with Homebrew, keg-only curl needs
`$(brew --prefix curl)/lib/pkgconfig` on `PKG_CONFIG_PATH`). CWIST's own
library directories are always searched first, so the bundled BoringSSL is
linked even when another OpenSSL is installed.

## What `cwist-sys` binds

Only what the safe wrapper needs, via the allowlist in
`cwist-sys/build.rs`: app lifecycle and routing (including the
`cwist_app_*_ex` routes that carry a user context), in-memory dispatch,
request/response strings and headers, error values, the `_extern` forms of
`static inline` helpers, and the advanced surface the safe wrappers cover:
safe strings (`cwist_sstring_*`), the SQLite wrapper (`cwist_db_*` plus the
hook-aware `cJSON_PrintUnformatted`/`cJSON_Delete`/`cJSON_free`), the
background scheduler (`cwist_scheduler_*`), JWT verify/claims
(`cwist_jwt_verify` and friends; `cwist_jwt_sign` was already bound),
SipHash-2-4 (`siphash24`, `cwist_generate_hash_seed`) and the bump arena
(`cwist_arena_*`). `cwist_app`, `cwist_query_map`, `cwist_db`, `cJSON`,
`sqlite3`, `cwist_async`, `cwist_compress_backend`, `cwist_scheduler_t` and
`cwist_arena_t` are opaque.

The struct layouts the bindings mirror are pinned on the C side by
`tests/abi_layout.h`, and bindgen checks the generated layouts against the C
compiler when the crate builds.

## The `cwist` crate

```rust
let mut app = cwist::App::new()?;
app.get("/users/:id", |req, res| {
    let id = req.param("id").unwrap_or("?");
    let _ = res.set_body(format!("user {id}"));
})?;
let response = app.dispatch(b"GET /users/7 HTTP/1.1\r\nHost: localhost\r\n\r\n")?;
```

* `App` owns the C app and destroys it on drop.
* Handlers are `Fn(&Request, &mut Response) + Send + Sync + 'static`
  closures, boxed and registered through the `cwist_app_*_ex` routes; CWIST
  drops each one exactly once (app drop, route replacement, or failed
  registration).
* `Request` and `Response` borrow the C objects for one handler call only.
* An unwinding panic in a handler (or in a handler's `Drop`) is caught at
  the C boundary; a panicking request is answered with 500. Caught panic
  payloads are intentionally leaked because their destructors can panic
  again. This does not catch aborting panics (`panic = "abort"`).
* `App::dispatch` runs a request in memory. Serving on a port (`listen`),
  with graceful shutdown, is `App::listen(port)`; see "Serving" below.
* Middleware is `Fn(&Request, &mut Response, &dyn Fn()) + Send + Sync +
  'static`, registered with `App::use_middleware` through
  `cwist_app_use_ex` and run in registration order around the route
  handler. Calling `next` runs the rest of the chain once (later calls do
  nothing); not calling it short-circuits the request. CWIST drops each
  middleware exactly once (app drop or failed registration), and a
  panicking middleware answers 500 without continuing the chain.

## Memory

Rust allocations stay outside `cwist_alloc`: CWIST's full GC and
`CWIST_INTERCEPT_MALLOC` do not apply to Rust code. Buffers CWIST returns
(for example from `cwist_app_dispatch_memory`) are released with `cwist_free`.
A route context registered with a destructor belongs to the app, which calls
the destructor exactly once.

## Advanced wrappers

Six modules wrap the "advanced/dangerous" FFI surface. Each owns its C handle
and releases it on `Drop`; strings crossing the boundary reject interior NUL
bytes with `Error::InteriorNul` instead of truncating.

* `SString` (`cwist::SString`) is an owned `cwist_sstring`. `assign`/`append`
  use the `*_len` entry points, so any `&str` works, embedded NUL bytes
  included; `as_bytes` reads the public `data`/`size` fields. Destroyed with
  `cwist_sstring_destroy`.
* `Db` (`cwist::Db`) wraps one SQLite connection (`cwist_db_open`,
  `cwist_db_open_memory`, closed by `cwist_db_close` on drop). `exec` and
  `query` pass SQL to SQLite **verbatim** — there is no parameter binding,
  so build and validate statements in Rust before they touch user input or
  you have a SQL injection hole. `query` prints the `cJSON` result with
  `cJSON_PrintUnformatted` and deletes the tree with `cJSON_Delete`.
  CWIST installs cJSON hooks (a constructor in `core/mem/alloc.c`) that
  route cJSON's allocator through `cwist_malloc`/`cwist_free`, so the printed
  buffer is released with the hook-aware `cJSON_free`, never raw libc free.
  `serialize` returns an image allocated by CWIST, freed with `cwist_free`;
  the image round-trips through `Db::open_memory`. `Db` is neither `Send`
  nor `Sync`: one connection, used from its owner thread.
* `Scheduler` (`cwist::Scheduler`) is a worker pool plus delayed task queue
  (`cwist_scheduler_*`). Jobs are boxed `FnOnce() + Send` closures; the
  worker reconstructs the box, runs it, and drops it, with `catch_unwind`
  at the trampoline so a panic never unwinds into C. A job that cannot be
  queued is dropped by the caller. `schedule` takes a `Duration` and waits
  at least that long before running the job. Dropping the scheduler joins
  the workers, so started jobs finish, but any job still queued or delayed
  is freed by CWIST without running: one boxed closure per unrun job leaks
  (memory leak only, no UB, and no C API exists to cancel or drain them).
  It is `Send + Sync`: the queue
  is mutex-protected and its `running` flag is atomic, and CWIST documents
  the scheduler as the background task queue for request handlers.
* `jwt` (`cwist::sign`, `cwist::verify`, `cwist::Claims`) is HMAC-SHA256
  JWT. `sign` frees the token with `cwist_free`; `verify` returns
  `Error::InvalidToken` for a malformed, mis-signed or expired token, and
  the claims are destroyed with `cwist_jwt_claims_destroy` on drop. Values
  from `Claims::get` borrow the claims and cannot outlive them.
* `siphash` (`cwist::Key`) wraps `siphash24` and `cwist_generate_hash_seed`.
  A `Key` is 16 bytes; `hash` returns the 64-bit SipHash-2-4 of a slice.
  Keys are cheap: `generate` for a random key, `from_bytes` to supply one.
* `Arena` (`cwist::Arena`) is a request-scoped bump allocator
  (`cwist_arena_*`). `alloc_bytes` returns zeroed memory — CWIST's chunks
  are uninitialized, so the wrapper zeroes them before handing out a safe
  slice. An exhausted generation returns `None` (the C contract is to fall
  back to the heap); memory is released in bulk on drop, no individual
  frees. Soundness rests on the borrow rules: every allocation takes
  `&mut self` and returns references bounded by that borrow, so `Drop`
  cannot run while one is live. `unsafe fn alloc_uninit<T>` is the
  zero-copy escape hatch for callers who write the contents themselves and
  handle initialization and drop contracts (the arena never runs
  destructors).

## Serving

```rust
let mut app = cwist::App::new()?;
app.get("/stop", |_, res| {
    cwist::shutdown();
    let _ = res.set_body("bye");
})?;
app.listen(8080)?; // blocks until cwist::shutdown() or SIGTERM/SIGINT
```

* `App::listen` serves in the calling process only: it passes one worker to
  `cwist_app_listen_ex`, so CWIST never forks and `CWIST_WORKERS` is ignored.
* It uses the reactor (C1M) server, whose handler threads are joined before
  `listen` returns; the app is then destroyed and its handlers dropped.
* `cwist::shutdown()` wraps `cwist_shutdown_request()`: callable from any
  thread or handler, idempotent, and process-wide like SIGTERM/SIGINT.
* One server per process: a second concurrent `listen` returns
  `Error::AlreadyListening`.
* CWIST fills unset `CWIST_*` tuning variables with `setenv` when `listen`
  starts; do not touch the environment on other threads meanwhile.
